# 구현 계획

## 구조
| 파일 | 하는 일 |
|---|---|
| `streamlit_app.py` | 화면(로그인, 학생, 관리자). 2.7절 key를 그대로 씀 |
| `tf/logic.py` | 규칙 엔진(순수 함수): 지원/투표/마감 결정, 필수 역할 자리 계산, 배정안 검사, 전수 탐색 배정, 배정 불가 이유 |
| `tf/db.py` | Supabase(Postgres) 계층: 연결 풀, 트랜잭션 + advisory lock, 결정을 DB에 반영 |
| `tf/ai.py` | 오픈라우터 호출: 1/2/3차 모델, 모델별 120초 전체 시간 제한, 응답 파싱 |
| `tf/roster.py` | 명단 CSV 읽기(`utf-8-sig`) |
| `schema.sql` | `tf_` 테이블과 제약. 앱이 시작할 때 그대로 실행 |
| `scripts/keepalive.py`, `.github/workflows/keepalive.yml` | 매일 DB 질의 |
| `tests/` | 연습용 시나리오 3개, DB 계층, AI 실패 처리 시험 |

## 고른 해결 방법 (3장 표)
| 기능 | 해결 | 구현 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `@st.fragment(run_every=3)`로 팀 목록/투표/팀이 없는 학생을 3초마다 다시 그림 |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | `logic.join_violation`이 지원 때 남는 자리 < 못 채운 필수 역할 수이면 막음(크기 2 매칭으로 셈) |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 마지막 찬성이 들어온 순간 `join_violation`을 다시 검사(투표가 끝난 순서대로 처리) |
| 마지막 자리에 두 명이 동시에 | 어려운 해결 | `tf_members` 기본 키 `(team_id, slot_no)` + `student_id` 유일 + `slot_no between 1 and 4` |
| AI 응답이 늦을 때 | 어려운 해결 | 요청을 스레드로 보내고 바깥에서 120초 전체 시간을 재서 끊음 |
| 3차 모델까지 실패 | 어려운 해결 | `logic.solve` 백트래킹으로 다섯 가지 검사를 모두 통과하는 배정을 끝까지 찾음 |
| AI 대기 중 화면 | 어려운 해결 | `assign_status` 안에 "N차 모델 … 응답을 기다리는 중 (경과 초 / 120초)"와 앞 시도 결과 |
| DB 일시정지 막기 | 어려운 해결 | GitHub Actions 예약 작업이 매일 `select` + `tf_settings` 갱신 |

## 동시성
쓰기 요청은 모두 `pg_advisory_xact_lock`으로 한 줄로 세운 뒤 상태를 읽고 결정한다. 그래도 겹치면 DB 유일성 제약이 막고, 앱은 "막힘"을 보여 준다.

## 단계
1. 규칙 엔진과 연습용 시나리오 시험(`tests/test_scenarios.py`)
2. 스키마와 DB 계층, 실제 Postgres로 어려움 시나리오 시험(`tests/test_db.py`)
3. AI 호출과 실패 처리 시험(`tests/test_ai.py`, 오픈라우터를 부르지 않음)
4. 화면과 key, 브라우저로 쉬움 시나리오 확인
5. Supabase 연결, Streamlit Community Cloud 배포, Secrets 설정, 공개 설정
6. 연습용 시나리오 3개를 배포한 앱에서 직접 해 보고 README 5~7항 작성

## 시험 방법
```
pip install -r requirements.txt pytest
pytest -q                                   # 규칙 엔진, AI 실패 처리
TEST_DATABASE_URL=... pytest -q             # DB 계층까지 (테이블을 지우므로 시험용 DB에만)
```
