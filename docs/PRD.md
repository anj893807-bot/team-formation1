# PRD: 팀 프로젝트 팀 편성 웹 앱

## 1. 목적
학생들이 팀 프로젝트의 팀을 스스로 편성한다. 모집이 마감된 뒤 팀이 없는 학생은 AI(오픈라우터)가 배정안을 내고, 앱이 그 배정안을 규칙으로 검사한다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생 | 학번과 비밀번호(1234)로 로그인. 팀 목록, 팀원, 팀원의 주/보조 역할을 봄. 팀에 지원. 내 팀에 들어온 지원에 찬성/거부 |
| 관리자 | 학번 `admin`과 `ADMIN_PASSWORD`로 로그인. 명단 CSV와 팀 수로 처음 상태를 만듦. 모집 마감. AI 배정안을 받아 확인하고 확정 |

## 3. 역할
기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개(명단 CSV에 정해짐).

## 4. 팀 규칙
1. 팀 수는 관리자가 명단을 올릴 때 정함(팀1, 팀2, …).
2. 확정한 팀은 모두 2~4명(빈 팀 없음).
3. 한 팀에 주 역할이 같은 학생이 2명 이상이면 안 됨.
4. 모든 팀에 기획자와 웹 프로그래머를 맡을 학생이 서로 다른 사람으로 1명씩 있어야 함(주 역할이나 보조 역할).

## 5. 지원과 투표
| 상황 | 결과 |
|---|---|
| 빈 팀에 지원 | 바로 승인 |
| 팀원이 있는 팀에 지원 | 대기. 투표하는 때의 팀원 모두가 투표 |
| 모든 팀원이 찬성 | 승인 직전에 규칙(정원, 주 역할 중복, 필수 역할 자리)을 다시 검사해 통과하면 승인, 아니면 거절 |
| 한 명이라도 거부 | 바로 거절 |
| 막힘(접수하지 않음) | 모집 마감, 이미 팀이 있음, 결과를 기다리는 지원이 있음, 팀이 꽉 참, 같은 주 역할의 팀원, 필수 포함 역할 자리가 모자람 |
| 투표 | 한 번 하면 바꿀 수 없음 |

필수 포함 역할 자리: 지원자가 들어간 뒤 남는 자리 수 < 아직 채우지 못한 필수 역할 수이면 막는다. 한 학생이 기획자와 웹 프로그래머를 둘 다 할 수 있어도 하나로만 센다.

## 6. 마감과 배정
1. 마감하면 대기 중인 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐.
2. AI 배정: 팀이 없는 학생만 배정. 1차 → 2차 → 3차 모델 순서. 모델마다 전체 대기 시간 120초.
3. 배정안 검사 다섯 가지: 빠짐없이 배정, 한 학생은 한 팀, 모든 팀 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족.
4. 실패(시간 초과, HTTP 오류, 빈 응답, 형식 오류, 검사 실패)면 다음 모델. 3차까지 실패하면 앱이 모든 경우를 따져 배정.
5. 규칙을 지키는 배정이 없으면 AI를 부르지 않고 이유를 보여 줌.
6. 관리자가 확정하면 DB에 저장.

## 7. 화면 요소 key (자동 채점용)
`login_student_no`, `login_password`, `login_submit`, `whoami`, `result`, `team_{n}`, `apply_{n}`, `vote_yes_{학번}`, `vote_no_{학번}`, `admin_roster_file`, `admin_team_count`, `admin_start`, `admin_close`, `unassigned`, `admin_assign`, `assign_status`, `admin_confirm`.
`result`의 첫 단어는 승인/대기/거절/막힘 가운데 하나.

## 8. 비기능 요구
- 다른 사람의 변경은 `st.fragment`로 3초마다 자동으로 다시 표시.
- 비밀번호는 bcrypt 해시로 저장. 키와 관리자 비밀번호는 `.env`/Streamlit Secrets에만 둠. 화면과 로그에 키를 출력하지 않음.
- DB 연결은 풀 하나를 다시 씀. 테이블 이름은 `tf_`로 시작.
- DB 유일성 제약으로 마지막 자리에 두 명이 동시에 들어가면 먼저 도착한 학생만 기록.
- GitHub Actions로 매일 DB에 질의해 Supabase 일시정지를 막음.
- 화면의 시각은 한국 시각.

## 9. 범위 밖
